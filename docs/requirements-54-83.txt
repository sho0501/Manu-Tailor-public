==================================================
54. 配布形態【重要】
==================================================

Manu-Tailorには大きく2種類の利用者がいます。

A. 管理者・マニュアル作成者
B. AI変換されたマニュアルを受け取る現場利用者

管理者側はWebブラウザを中心とします。

現場利用者側は必ず以下の3形式に対応できる構成にしてください。

1. Android APK
2. iOS IPA
3. Webブラウザ / PWA

3種類を完全に別々のコードベースで作ってはいけません。

可能な限り1つのUIコードベースから展開してください。


==================================================

・GitHub Actionsのみでビルド可能
・Windowsで通常開発可能
・Android Studioを常時必要としない
・Macを所有していなくてもiOSコードを開発できる
・最終ビルドはGitHub ActionsのmacOS runnerで可能

を優先してください。

==================================================
57. 通知機能
==================================================

通知を主要機能として実装してください。

通知対象：

・新しいマニュアルが公開された
・割り当てられたマニュアルが更新された
・管理者から重要なお知らせ
・安全上重要な改訂

通知を押した場合は
対象マニュアルへ直接遷移してください。


通知方式はProviderとして抽象化してください。

NotificationProvider

例：

Web:
Web Push / Service Worker

Android:
Firebase Cloud Messaging等

iOS:
APNsまたはFCM経由


特定サービスに密結合しないようにしてください。

Push通知用資格情報が無い開発環境では、

MockNotificationProvider

を使用してください。

Mockでも

管理者が公開
↓
利用者アプリに通知表示
↓
マニュアルを開く

というデモができるようにしてください。

==================================================
59. オフライン対応
==================================================

工場等では通信が不安定な可能性があるため、

一度開いたマニュアルは端末へキャッシュできるようにしてください。

最低限：

・最近開いたマニュアル
・現在作業中のマニュアル
・画像
・必要な原文情報

をオフラインで閲覧可能にしてください。

ただし最新版でない場合は

「このマニュアルは最新版ではない可能性があります」

等の表示をしてください。

Safety Modeの場合は
古いキャッシュを利用できる条件を厳しくしてください。

60. デザイン方針
==================================================

UI/UXの完成度を非常に重視してください。

単なる開発者向けBootstrap風画面ではなく、

「初めて触った人でも説明なしで使える」

ことを目標としてください。


ブランドイメージ：

・白を基調
・明るい青 / シアンをアクセント
・濃紺に近い読みやすい文字
・丸みのあるカード
・十分な余白
・シンプルなアイコン
・軽い影
・清潔
・安心感
・業務アプリだが堅苦しすぎない

発表資料のManu-Tailorの
白 + 青系のイメージを参考にしてください。


禁止：

・情報を詰め込みすぎる
・小さい文字
・小さいボタン
・色だけで状態を区別
・大量の枠線
・大量の設定項目を1画面に並べる
・専門用語だらけ
・開発者向け管理画面のような利用者UI

==================================================
68. GitHub Repository
==================================================

このプロジェクトはGitHubのPRIVATE repositoryで管理してください。

Public repositoryにしてはいけません。

リポジトリ名の第一候補：

Manu-Tailor

GitHub CLIが利用可能なら、

gh auth status

で認証状態を確認してください。

認証済みで、
Manu-Tailor repositoryがまだ存在しない場合：

gh repo create Manu-Tailor \
  --private \
  --description "Adaptive manual generation platform" \
  --source . \
  --remote origin

等の方法でPRIVATE repositoryを作成してください。

実際のコマンドはWindows PowerShell環境に合わせてください。

作成後、

gh repo view --json nameWithOwner,visibility

等で必ず

visibility = PRIVATE

であることを確認してください。

既に同名repositoryが存在する場合は、
削除や上書きを行わず内容を確認してください。

絶対に既存repoを勝手に削除しないでください。

73. iOS GitHub Actions
==================================================

iOSは

runnerでビルドしてください。

を行えるworkflowを作ってください。

証明書やProvisioning Profile等が用意されていない状態で

資格情報が存在しない場合：

・iOS projectのbuild検証
・Simulator build
または
・unsigned archive

まで行ってください。


署名情報がGitHub Secretsに設定されたら
installable IPAを生成できるworkflowを完成させてください。


想定Secrets：

APPLE_CERTIFICATE_BASE64
APPLE_CERTIFICATE_PASSWORD
APPLE_PROVISION_PROFILE_BASE64
APPLE_TEAM_ID
APPLE_BUNDLE_ID

必要な名称は実装に合わせて整理してください。
