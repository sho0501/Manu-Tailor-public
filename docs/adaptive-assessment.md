# 適応型表示チェック（要件84〜119）

## 使い方

1. 利用者でログインし「表示の好みをチェック」を開きます。
2. 希望言語を選び、1画面ずつ表示される質問で文章・図・文字サイズ・行間などの好みを選びます。最後に約3分または詳細モードを選ぶと仮想問題が始まります。日本語以外では日本語の読みや使用頻度を尋ねません。
3. 画面の仮想問題に回答します。必要な範囲の観測と確信度が得られると終了します。「ここまでで表示を提案」でも終了できます。
4. 「この設定で使う」で保存します。表示は閲覧時、文章変換は次の個別生成に反映されます。
5. 管理者は「利用者 → 表示チェックの記録」で回答履歴・選問理由・推定値・確信度・時間を確認できます。利用者間の順位表はありません。

`assessment-a` / `assessment-b` / `assessment-c` / `assessment-d` は合成デモです。パスワードは既存デモと同じ `manutailor-demo`。Aは短文とふりがな、Bは3手順、Cは1手順と否定表現の支援、Dは短文・ふりがな・図の併用を提案します。実測や学習データではありません。

## 推定方法

各領域に0〜1の41点の事前分布を用意し、項目の難易度・識別係数・選択肢から定めた正答尤度でベイズ更新します。正答率をそのまま能力値にはしません。確信度は事前分散からの減少量です。推定値の正しさの確率ではありません。

初期の簡単な項目、漢字の段階的確認、同内容の形式比較を優先し、その他は期待エントロピー減少と未測定領域の重みで選びます。Quickの主要領域を先に確認します。Quickは12問以上、主要領域の観測あり・各確信度0.08以上・平均0.22以上で暫定提案を終了できます。詳細は20問以上、全領域の観測と平均0.45以上です。時間上限180/600秒、問題上限24/バンク件数＋生成枠10、バンク枯渇でも終了します。不足は支援ありの既定設定へ戻します。

この閾値・難易度はPoC用の仮値です。短時間で高い測定精度が得られるとの主張はしません。実利用者の同意に基づく比較と校正が必要です。

好みは `preferences`、正誤・比較結果は `performance`、分布要約は `skills` に分離してSQLiteへ保存します。時間は同じ利用者の対になった正答同士でのみ比較し、別タブへ移動した回答は時間比較から除きます。サーバーの経過時間を超えた自己申告時間は切り詰めます。短時間の回答だけでは能力を加点しません。同内容の繰り返しには練習効果が残るため、比較結果は暫定です。

## 問題とAI

問題バンクは版・特徴量・正答・説明・出自を持ちます。初期問題はPoCの作成済み例題で、人間の確認済みとは表示しません。管理者の「問題バンクの確認」で人間が問題と正答を確認した記録を残せます。人間による全例題のレビューと、実測による校正は導入前の残作業です。

生成枠は最大約25%。生成Agentは設定済みの生成Providerを利用し、現在の推定・既出問題・構造化された制約を入力します。Mockでは同じ制約からパラメータを選びます。PoCの自動公開対象は色・物体の許可リストを使う仮想指示テンプレートです。Validatorが問題と一意な正解を再構築し、自由文や範囲外のパラメータは拒否します。最大2回、全体10秒でバンクへ戻ります。一般的な自由生成問題の自然さ・正解一意性を保証できるとは扱いません。

選択肢の位置はセッションごとに回転します。通常利用者APIは正答・内部推定を返しません。質問の所有権、回答形式、重複送信を検証します。原文マニュアルや入力文をシステム指示として実行しません。

## 表示への反映

- `max_sentence_chars`：文の目標長を生成Providerへ渡し、Mockでは既存句読点で改行。閲覧時の折り返し幅にも使用。原文を切り捨てて文字数を強制しません。
- `steps_per_screen`：1〜3手順を実際に表示し、次へ・戻るも同じ単位で移動。
- `use_furigana`：業務用語辞書に登録された語をruby表示。未知語の読みは捏造しません。
- `font_scale` / `line_spacing`：表示へ直接適用。
- 図の推奨：既存の `visual_support` と一緒に保存。`prefer_images` で文章の前後を切り替え、元の画像は保持します。
- 否定表現：原文の禁止を残し、完全一致する検証済み文だけ肯定形の補助を表示。未検証の否定文を自由に反転させません。
- `use_bullets`：改行した文章を箇条書き表示。
- `highlight_warnings`：注意事項の強調を調整。オフでも警告本文は消しません。

## 小規模モデル

| 候補 | 採用判断 |
| --- | --- |
| ルール＋ベイズ | 初期採用。データ不足でも不確実性を保持し、説明可能 |
| ロジスティック回帰 | 同意・適合ラベルが集まった後の比較用に学習・保存・予測クラスを実装 |
| LightGBM / XGBoost | 多様な実測データが集まり、非線形な関係を検証する段階で比較 |
| 小規模ニューラルネット | 現在は学習データ不足で採用しない |
| 小型言語モデル | 問題パラメータ生成に使用可能。利用者の能力を自由推論させない |

`app.profile_prediction.ProfilePredictionModel` は特徴量8個から表示設定5項目の適合確率を推定します。文字サイズと行間は現時点で本人選択を優先します。50件・10利用者以上、全件の同意と人間による適合ラベル、両クラスを要求します。同一利用者が学習側と評価側へ混ざらない分割でBrier scoreを記録します。自動学習・自動適用はしません。

入力JSONの1行の形：`{"group":"anonymous-1","consent":true,"features":[0.6,0.7,0.6,0.1,0.2,0.3,0.8,1],"targets":{"use_furigana":true,"short_sentence":true,"prefer_images":true,"one_task_per_screen":true,"highlight_warnings":true}}`。ファイル全体は配列です。実測ラベルは未収集です。

```powershell
# 同意済みデータをFドライブに置いた後、必要な場合に明示実行
$env:PYTHONPATH = "$PWD\apps\backend"
.\.venv\Scripts\python.exe -m app.profile_prediction .\data\consented-display-labels.json
```

成果物は `models/profile/logistic-v1.json`。モデル・入力データはGitへ含めません。

## 継続利用とプライバシー

本人が設定画面で記録を許可した場合のみ、戻る・原文確認・文字拡大をサーバーへ送信します。直近500件に制限し、頻度に応じた提案を設定画面に表示します。提案の取り込みと保存は本人操作です。既存の評価結果を適用しても、過去の同意状態へ巻き戻しません。管理者が評価記録を閲覧した事実は監査ログに残ります。

障害名・病名・能力ラベルは保存しません。結果はSQLite内の個人データとして扱ってください。言語コードは保持しますが、今回の問題本文は日本語です。
